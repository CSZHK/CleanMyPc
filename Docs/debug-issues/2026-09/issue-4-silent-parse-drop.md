# Issue #4: 宽松正则静默丢行，规则可被绕过

**修复日期**: 2026-09-15
**类别**: 其他（门禁工具）
**关联模块**: `scripts/atlas/copy_gate.py`
**严重等级**: 未定级（门禁有效性缺陷，非产品故障）

---

## 问题本质 (≤3行)
写成 `"k" = "v" ;`（分号前空格）或带行尾注释即可绕过全部 8 条规则。
触发条件：`LINE_RE` 不匹配的行被静默丢弃，且**键计数不变**，C7 parity 也不报警。

## 根因分析 (≤5行)
`LINE_RE = ^\s*"([^"]+)"\s*=\s*"(.*)";\s*$`（`scripts/atlas/copy_gate.py:117`）不容忍分号前空格与行尾注释。
`load_strings()` 只写 `if m:`，无 else 分支、无丢弃计数——解析层没有任何
「读进来多少行 vs 预期多少行」的断言，被丢的行从体系里消失且无痕。
这与仓库已修过的「零 UI 用例仍 exit 0」是同一类静默空转。

## 解决方案 (≤5行)
新增 C10 解析完整性维，逐行核对非空非注释行是否都被 `LINE_RE` 匹配到。
- 关键代码: `scripts/atlas/copy_gate.py:266-286`（`check_parse_integrity`）
块注释按状态逐行判（`/* */` 可跨行），避免把续行误报为未解析内容。

## 关键决策 (≤3行)
C10 计入阻断维而非报告维：解析丢失会让所有其他维的「绿」失去意义。
注释过滤按状态机而非「行首是否 *」，否则 header 注释的续行会触发误报。

## 预防措施 (≤2行)
任何解析器都要断言「读进来多少」：丢弃必须可见（计数或报错），静默丢弃不可接受。
已做变异检验：注入 `"zz.probe" = "x" ;` 即 C10 变红。

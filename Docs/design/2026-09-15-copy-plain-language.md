## 1. 问题

用户反馈「UI 的固定信息表述对普通用户不友好」。回源后确认这不是零散措辞问题，而是**系统性的一类**，分四型：

| 型 | 表现 | 实例（改动前） |
|---|---|---|
| **A. 屏幕副标题写成设计规格句** | 每个屏首屏第一句是在向评审者交代设计取舍，用户读完不知道自己能干什么 | `permissions.screen.subtitle` =「**先解释为什么需要访问**，保持受限模式可用，并且只在具体流程真正需要时再打开系统设置。」——这是验收条款原文，主语是开发者 |
| **B. 术语黑话** | 中文侧使用会计/法律/公文隐喻 | 台账 52 处 · 复核 78 处 · 证据 34 处 · 发现项 18 处 · 回执 17 处 · 足迹 · 入账 · 作废 · № |
| **C. 说明性长句** | 文案在解释设计，不在告知事实 | 42 条超 40 宽；最长 143 宽（`infrastructure.permission.fullDiskAccess.needed`） |
| **D. 自指与开发备注** | 同屏同名；开发备注直接渲染给用户 | `storage.screen.subtitle` =「为未来版本预留的基于列表的存储视图。」 |

**规模**：132 个 key 的文案值含隐喻词，跨 20 个 key 前缀 · 全部 6 个 feature 包。

## 2. 根因

**不是「文案写得不好」，是目标函数单一。**

既有术语基线（`REQ-ux-friction-remediation` 的 Wave 0，2026-09-14 签字）把「**消除歧义**」当成唯一判据。为消歧，出现了：

- 为「已归档」一词两义 → 拆词（正确）
- 为消除同屏撞名 → 改 chip（正确）
- **为统一口径 → 引入整套公文隐喻**（错误）

每一条单独看都成立，累积起来把中文文案推向了法律文书般的精确度，代价是牺牲可读性。**契约里没有一条约束「用户第一次看到这个词能不能懂」。**

**放大器**：`Docs/COPY_GUIDELINES.md` 的 Tone / Product Voice / Good Patterns **全部为 en 单语**，中文侧从无语气规范。写中文的人没有判据可依，只能向上游设计规格要语言 —— 于是规格句被原样搬进界面。这是**结构性**原因，不补它同样的退化会再发生。

## 3. 判据

### 3.1 目标函数（两条，冲突时可读性优先）

1. 非技术 Mac 用户第一次看到，能懂吗？
2. 它准确描述了实际会发生的事吗？

冲突时**可读性优先**；歧义用**拆词**解决（一词一义），**不用生僻词解决**。

### 3.2 术语退役表（P 系列）

完整对照与逐词理由见 `iterations/REQ-copy-plain-language/terminology-baseline.md`。摘要：

| 旧 | 新 | 旧 | 新 |
|---|---|---|---|
| 台账 / `Ledger` | 历史记录 / `History` | 发现项 / `finding` | 清理项 / `item` |
| 回执（标识符） / `Receipt` | 编号 / `ID` | № | `#` |
| 回执（阶段/面板名） | **结果** / `Results` | 已作废 / `Superseded` | 已失效 |
| 应用足迹 / `Footprint` | 应用占用 / `App Storage` | 入账 | 已记录 / `Recorded` |
| 证据（扫到但不删） / `Evidence` | 未删除项 / `Not removed` | 主流程 / `core workflows` | 主要功能 / `main features` |
| 证据（FO 分类理由） | **分类依据** / classification reason | 保留窗口 | 保留期 / `retention period` |

**保留不动**（明确列出，防下一轮重开）：恢复点 · 复核 · 受限模式 · 残留 · 清理计划/卸载计划/扫描/计划 · macOS 系统权限名。

### 3.3 语域规则（反转）

`COPY_GUIDELINES.md` 原 Containment Rules 规定「文书语气**仅限**台账面（warm paper）；工作面用直白动词」。

**本次裁定：双轨合一，全产品单一语域：白话直陈。** 该规则失去指称对象 —— 台账面这个语域不复存在。

工作面的「直白动词」规则继续有效。**内部标识不受约束**：Swift 符号名 / 键名 / 包名 / 路由 case / 设计面内部代号都不是面向用户的词。

## 4. 执行方式：门禁先行

**待办列表由机器生成，不是靠人读 1166 条文案。**

```
写门禁规则 → 对现状跑一遍 → 红清单即待办 → 逐条消灭 → 全绿即完成
```

三条收益：**完备**（规则覆盖到的都进列表）· **可计数**（完成判据是「红 = 0」）· **抗守卫空转**（规则即判据，不存在「断言看着对但没测到」的空间）。

实现：`scripts/atlas/copy-gate.sh` + `scripts/atlas/copy_gate.py`，八条规则（C1–C8），哨兵 `ATLAS_COPY_GATE=PASS|FAIL:N|NOT_RUN`。

**门禁卫生**：前置不满足返回 **2** 并打印 `NOT_RUN`，**不得计为通过** —— 对照 `run-ui-automation.sh` 曾在 AX 未授权时 `exit 0` 的反面案例（该案例已由 `REQ-ux-friction-remediation` 裁定加固）。

## 5. 波次与实测

| 波 | 内容 | 结果 |
|---|---|---|
| P1 | 门禁建立 + 现状基线 | 阻断维红 **263** 条（C1 217 / C2 7 / C3 3 / C4 36） |
| P2 | 文案替换（脚本 4 遍，带占位符自检） | 263 → **0** |
| P3 | 回归修复 | `Packages` 612/2 → **613/0** · `Apps` **72/0** |
| P4 | 文档同步 | `COPY_GUIDELINES` 双语化 · Calm Ledger **v4** |

### 5.1 P2 的第 4 遍为什么必须存在

前 3 遍跑完**门禁已经 PASS**。第 4 遍是**人读**发现的、机器判据覆盖不到的三类：

1. **一词两义被机械替换抹平** ——「回执」既作阶段条/面板名，又作标识符。统一译成「编号」后阶段条读出「扫描 / 复核 / 执行 / **编号**」。裁定：阶段/面板名 →「结果」；标识符 →「编号」
2. **冗余** ——「占用与残留占用」「全程录入历史记录」「通过恢复历史记录保留可追溯性」
3. **开发备注直接渲染给用户** —— `storage.screen.subtitle`

> ⚠️ **这是本次最容易被漏掉的一遍。** 门禁全绿 ≠ 文案能用。任何「以门禁通过为收口」的流程都必须显式安排这一遍，否则交付的是「符合规则的坏文案」。
